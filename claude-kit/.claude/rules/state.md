# Состояние и данные

- Состояния — sealed-класс: `Initial`, `Loading`, `Success(data)`, `Failure(error)`. Данные существуют только в `Success`; nullable-полей «на время загрузки» нет.
- Bloc запускает загрузку при создании. Загрузка по действию пользователя (например, по вводу в поиск) — только если это и есть суть действия.
- Действия с переходом или запросом — `bloc_concurrency`: `droppable()`; поиск — `restartable()` с debounce.
- Лайки, переключатели и похожие действия — оптимистичное обновление: сразу новое состояние, при ошибке откат и `AppToast`.
- Источник истины — репозиторий с кэшем. Bloc сначала отдаёт кэш, затем обновляет его. Данные, нужные при холодном старте, — через `hydrated_bloc`.
- Каждая ошибка репозитория возвращается как типизированный результат с кодом. `BlocObserver` отправляет ошибки в Sentry. Пустых `catch` нет.
- Каждый Bloc покрыт `bloc_test`: успех, ошибка, повторный вызов во время выполнения.
